# UTF-16LE Null-Byte Normalization and Authorized VA Scanner Rigidity

When SOC analysts paste standalone PowerShell `-EncodedCommand` payloads directly from SIEM alerts or process telemetry without the wrapping `powershell -enc` prefix, `cmd-unmask` must automatically decode raw Base64 inputs, normalize **UTF-16LE Null-Byte Padding** (`\x00` interleaved between ASCII characters), and preserve multi-line `@' ... '@` PowerShell here-strings without corrupting inline C# (`Add-Type`) blocks—using 100% Python standard library (`base64`, `re`). Furthermore, enterprise credentialed vulnerability scanners (such as Tenable Nessus) routinely execute read-only WMI/P/Invoke audit scripts (e.g., `Netapi32.dll` `NetGetJoinInformation` domain-join checks). To preserve **Detection Rigidity** against False Positives, `cmd-unmask` distinguishes benign **Authorized Audit Baseline** P/Invoke signatures (read-only domain/OS queries) from offensive Win32 memory-injection P/Invoke APIs (`VirtualAlloc`, `WriteProcessMemory`, `CreateRemoteThread`, `OpenProcess`), ensuring authorized VA audit scripts triage cleanly while true process-injection stagers remain flagged.
