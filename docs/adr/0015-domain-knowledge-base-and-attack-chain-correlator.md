# Domain Knowledge Base and Attack-Chain Correlator

SOC Layer 1 analysts triaging unfamiliar LOLBins, obscure execution flags, or multi-signal alerts often spend extra minutes looking up what a binary normally does, whether a system binary running from `C:\Users\Public\` is masquerading, whether a destination IP is RFC1918 internal vs. cloud metadata vs. public C2, and what concrete containment or verification steps to run next. Relying on external LLMs or live threat-intel APIs violates `cmd-unmask`'s air-gap, zero-dependency, and sub-millisecond latency guarantees ([ADR-0001](0001-static-stdlib-only-analysis.md)).

To bridge this gap deterministically using 100% Python standard library (`dataclasses`, `ipaddress`, `pathlib`, `re`), `cmd-unmask` v0.7 introduces a static **Domain Knowledge Base** (`src/cmd_unmask/knowledge.py`) and **Attack-Chain Correlation** engine (`src/cmd_unmask/correlator.py`):

1. **Domain Knowledge Base (`knowledge.py`):** Embeds curated, read-only profiles for 40+ Windows/Linux LOLBins and system utilities, execution flag semantics (`-enc`, `-nop`, `-w hidden`, `/c`, `-ep bypass`, etc.), **Binary Masquerading** checks (flagging canonical OS binary names executed outside trusted OS directories such as `\Windows\System32\`, `\Windows\SysWOW64\`, `/usr/bin/`, `/bin/`), and deterministic network target classification (`ipaddress` RFC1918/loopback/link-local cloud metadata vs. public external vs. trusted vendor domains).
2. **Attack-Chain Correlation & Investigation Playbook (`correlator.py`):** Synthesizes multi-signal kill-chain narratives (`Delivery -> Evasion -> Execution / C2 / Impact`) from the Unpacking DAG, process lineage, behavioral matches, binary profiles, and IOC classifications, producing a concise **Analyst Executive Brief** and artifact-specific **Investigation Playbook** steps grounded directly in observed paths, domains, and MITRE techniques.
3. **Detection Rigidity:** Knowledge enrichment and playbook generation are additive and deterministic; **Binary Masquerading** detection applies strict canonical-path allowlists so normal OS execution in `System32`/`SysWOW64`/`Program Files`/`/usr/bin` never triggers False Positives (`FPR=0.0000`).
