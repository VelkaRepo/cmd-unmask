# Parent-Child Process Chain and Staging Path Triage

`cmd-unmask` extends static command-line analysis with optional **Process Lineage Context** (`parent_image`, `parent_command`, `image`) extracted from Windows Security Event ID 4688, Sysmon Event ID 1, and EDR/SIEM JSON telemetry—or supplied directly via `--parent`—using 100% Python standard library (`pathlib`, `re`, `json`, `dataclasses`) with zero external dependencies. Command-line text alone misses high-signal initial-access and lateral-movement patterns where benign-looking interpreters (`powershell.exe`, `cmd.exe`, `wscript.exe`) are spawned by Office applications (`winword.exe`, `excel.exe`), browsers, or web/SQL services (`w3wp.exe`, `sqlservr.exe`), or when binaries execute from user-writable **Staging Path Anomalies** (`\Users\Public\`, `\AppData\Local\Temp\`, `\ProgramData\`, `/tmp/`, `/dev/shm/`). Evaluating a deterministic **Spawn Matrix** and staging-path heuristics alongside the Unpacking DAG preserves backward compatibility when lineage fields are absent while enriching the `TriageVerdict`, SOC Ticket Note, and synthesized Sigma YAML (`ParentImage` / `Image` conditions) without risking False Positives on standard OS paths.
